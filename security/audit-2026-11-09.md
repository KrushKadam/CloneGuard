## Accepted Risk Item

**Registry fallback in `voiceprint.py` (lines 39–55)**

- **What:** `get_api_key()` reads `GNANI_API_KEY` from `HKCU\Environment` if not in process env.
- **Rationale:** Removing it risked breaking key setup for users who had already configured it via system env var before the contest deadline. The fallback is per-user, not machine-wide. Documented in threat model and secrets policy.
- **Mitigation:** README warns to prefer system env var over terminal paste. Post-deadline, the fallback should be removed.

## Open Recommendations

1. **Periodic dependency re-pin** — Run `pip list --outdated` monthly; update `requirements.txt` after testing.
2. **Remove registry fallback** — After 10 November 2026 deadline, delete the `winreg` block in `voiceprint.py`.
3. **Rotate any key ever pasted in chat/terminal** — If the key was ever pasted in PowerShell, VS Code terminal, or any chat, revoke at `app.gnani.ai` and generate a new one.
4. **Lower upload limit** — Consider 10 MB (covers typical call recordings; 25 MB is generous).
5. **Encrypt `voiceprints.json` at rest** — For shared-machine scenarios, add user-derived encryption.
6. **Run `pip-audit` in CI** — Add to pre-release checklist when CI is introduced.

## Overall Verdict

**Local-only breachability: LOW**

- No remote attack surface (localhost only)
- No code execution vectors (no pickle/eval/exec, no dynamic imports)
- Secrets management: environment variable only, never logged, never committed
- Data at rest: local JSON files, excluded from git, OS permissions are the control
- Cloud calls: HTTPS only, hardcoded endpoints, API key in header (TLS-protected)
- Supply chain: 6 pinned direct dependencies, no known vulnerabilities at audit date
